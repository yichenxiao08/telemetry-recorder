## Assessment adopted

Narrow to a local Python investigation aid for reproducible behavior and approved
synthetic inputs. Selected boundaries can be recorded, observations compared and
declared expectations checked. This implementation does not establish better
diagnosis than source reading, a debugger, targeted logs or tests. Persistent
comparable values across runs are a plausible advantage, not a demonstrated one.
No causal-proof, arbitrary-output explanation, production/privacy or market claim.

The critique's strongest objections are retained:

- Configuration may consume the benefit: functions/fields/state/run boundaries,
  references, setup and interpretation all take work. Scanner syntax/rank is not
  diagnosis or proof of a useful boundary. The old unbounded enumeration warning
  is stale after merged PR #30; other scanner limits remain.
- Selected argument/return capture can omit globals, prior mutation, internal
  branches, external effects, aliases, unsupported values, async/generators or
  sampled-out calls. Argument-to-output lineage does not prove actual dependence.
- Complete delivery means complete declared scope, not whole-program observation.
  The critique flags legacy envelope completeness checking inputs without
  requiring output capture. The verifier checks structured citations/facts and
  limited causal phrasing, not arbitrary prose meaning or explanatory truth.
- Strict P0 removes identity/rule/config/lineage metadata and may disable useful
  analysis. Original cost targets were missed; added costs and production privacy
  remain unestablished. Sampling/full-capture tradeoffs fit bounded local work.
- Run 2 had generous attribution and a six-command source baseline; run 3 was
  invalid. Run4b, run4c and historical-01 failed hard gates without tool testing.
  None establishes incremental diagnostic advantage or a Signal Scout failure on
  those untested cases.

The critique itself was a read-only targeted review: no execution or external
research, supplied evaluation summaries only, an older checkout checked against
cached main for scanner fixes, and no live PR/CI verification. Its high-confidence
implementation assessments are not independently executed product validation.

## Decisions

Defer Node implementation, LLM integration, value linking, first-divergence and
other expansion pending the paired pilot. PR #31 remains design-only reference.
Use three independent new real cases without screening for baseline failure.
Give both arms equal source access/ordinary experiments from first read; retain
complete zero-drop capture before runtime analysis, setup costs, losses, separate
source/scanner/runtime attribution and independent grading. After two failed
capture attempts permit source-only investigation within the original budget;
that correctness is not a tool Hit. Original hard-test access/gate rules stay.

The [pilot protocol](paired-usefulness-pilot.md) freezes the proposed practical
investment bar: three valid completed pairs; tool correct at least two; no paired
correctness regression; at least one runtime-supported cause-naming Hit associated
with a discordant correct tool solve or >=20% lower setup-inclusive elapsed where
both solve. Incomplete/invalid is inconclusive. Failure pauses expansion under this
thesis; passing supports another held-out evaluation only. Twenty percent is a
prospective practical policy, not statistical proof. No extending/tuning until pass.

Three agent pairs cannot establish average benefit, human usability or demand.
Prepared environments hide onboarding unless preparation costs are published;
public recognition, imperfect blinding/order, synthetic inputs and Windows-only
reproducibility limit generality. Repeated held-out advantages and voluntary
ordinary-developer adoption recovering setup cost would strengthen the case.
An audit/comparison pivot would need its own demand evidence, not relabeled
failure to demonstrate diagnosis gains.
