# Probe scan JSON contract, version 1

Closed top-level keys: schema_version (integer 1), candidates and unresolved (arrays of Candidate), coverage, exclusions, errors, truncations and limits. Arrays are always present, including empty lists. Candidate keys: file (relative slash path), line (positive integer), function, signals (string array), selector, unsupported_reason. Later candidate construction must supply either selector or a nonempty unsupported_reason; foundation emits no candidates.

Coverage keys: eligible, parsed, read (nonnegative integers), bytes (nonnegative integer), complete (boolean). Eligible excludes pruned trees; enumeration failures mean the true eligible total is unknown. complete requires no errors or truncations and describes only eligible scope, never excluded trees. Parsed/read and exclusions must always be shown together. Entry arrays contain path and reason; no source or exception text. Limits: max_files (1..2000), max_bytes (1..20000000). Stable traversal order and no timestamps make identical trees/settings byte-stable. JSON files are created exclusively, never overwritten.

Parsing uses a fixed Python ast.parse program with source bytes on stdin, -E -s -B, five-second per-file deadline and 1 KiB output bound. No target imports or execution. The trusted interpreter standard library starts normally; this is not a sandbox against a compromised interpreter. Syntax coverage depends on Python version. A stable source tree is required: concurrent hostile replacement of parent directories is outside this foundation's filesystem threat model. Links and reparse points found during enumeration are rejected rather than followed. Total parsing time can reach five seconds per admitted file. Enumeration counts all entries and is not a hard wall-clock/memory bound on arbitrarily huge directory trees.

## Additive steps 3-4 fields (schema_version remains 1)

Candidate retains every existing key and adds details (array of Signal), score, rank, tie_count (integers), config (YAML fragment string; empty for unsupported) and hot (boolean). Signal has kind, file, line, fact, tier. kind is one of the six implementation-note names. tier is observation except partial_dict_key, which is association; this is syntactic association, not statistical or causal evidence. signals remains the deduplicated kind array, and score is its length. Details provide file:line provenance. selector is empty when unsupported_reason is nonempty. Config capture is {}, i.e. OFF. Hot configs suggest incomplete deterministic sampling; text explains unknown unsampled calls and optional paired queue placeholders with memory estimates. Queue settings are never defaults. Each section is capped independently by --limit 1..200 (default 20). Rank and tie_count describe the full section before its cap. Truncations distinguish per-file analysis, scan read limits, primary and unresolved post-ranking limits. Complete is false for any error or truncation.

The original fixed parser remains for parse-only tests. CLI analysis uses a fixed embedded AST program with 4 MiB output cap and 256 candidate entries per file, reporting omitted counts; failures remain errors. Module resolution is relative to explicit --import-root, otherwise root-level modules and uninterrupted __init__.py package chains only. Ambiguous src/namespace layouts have no selector. No new top-level keys were introduced.
